# Dependency Recommendations

Status: **PROPOSED**. Constraint: **Go-only application, GUI included** — no React/Vue/Svelte, no HTML/CSS frontend, no Electron, no Wails, no separate JavaScript frontend. JavaScript libraries are permitted **only** inside the embedded script engine (Bruno compatibility) and for PAC evaluation.

Evidence for the Bruno dependency inventory these replace: `research/dependencies.md`.

## 1. GUI framework evaluation

**Decision recorded:** the GUI library is **MyGo** (`github.com/egoist/mygo`, native-UI mode), with **Lobe MyGo** (`github.com/lobehub/lobe-mygo`) as the component library on top of it. Sections 1.1–1.4 verify that choice and record the alternatives for context; the recommendation in §1.3 is therefore already settled, not open.

### 1.1.1 Component layer: Lobe MyGo (VERIFIED)

MyGo `ui` is a toolkit: it provides layout, input, drawing and a handful of broad widgets (`Tabs`, `List`, `Table`, `Sidebar`, `Tree`, `Menu`, `Modal`, inputs). It does **not** provide a design language — every app that uses it invents its own buttons, inputs, tags and menus. **Lobe MyGo** fills exactly that gap and is therefore the component layer:

| Attribute          | Value                                                                                                                                                                                                    |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Module             | `github.com/lobehub/lobe-mygo`                                                                                                                                                                           |
| Version observed   | `v0.0.0-…-5e5fea5` (pseudo-version; no tagged release at time of writing), docs dated 2026-11-10                                                                                                         |
| Licence            | MIT                                                                                                                                                                                                      |
| Build requirements | Go 1.27+ (this repo declares 1.27.3); **builds on MyGo**                                                                                                                                                 |
| Nature             | Pure Go, no cgo; components drawn by MyGo on the GPU; explicitly “no HTML, no JavaScript and no webview”                                                                                                 |
| Contents           | 70+ components across `pkg/{action,field,choice,display,feedback,overlay,nav,layout,code}`, plus `pkg/theme` (Lobe UI tokens), `pkg/motion`, `pkg/markdown`, `pkg/lucide` (2,300+ icons as Go functions) |
| Design language    | Generated from `@lobehub/ui`, so colours, radii and font sizes match Lobe UI rather than being invented                                                                                                  |
| i18n               | Ships English and Simplified Chinese; text overridable under the `lobe.<key>` namespace (`pkg/internal/l10n/messages/en.json`)                                                                           |
| Bundled example    | `examples/desktop` — a desktop skeleton with title bar, tabs with history, resizable sidebar, content card and settings form                                                                             |

Why this does not weaken the Go-only decision:

1. It is a Go library, not a frontend framework — `go get` and compile, no build step, no asset pipeline.
2. It paints through MyGo's native UI path, which the evaluation in §1.1 already selected.
3. It does not introduce a second toolkit; it is _inside_ MyGo.

Risk carried forward: the module is at a pseudo-version with no tags, so it moves like a `main` branch. Mitigation is identical to MyGo's (§1.3): pin the pseudo-version in `go.mod`, vendor it, and confine imports to `internal/ui/*`.

Source: `github.com/lobehub/lobe-mygo` — module README (package table, “Why Lobe MyGo?”, Getting Started) and the package docs for `pkg/theme`, `pkg/action`, `pkg/field`, `pkg/display`, `pkg/feedback`, `pkg/overlay`, `pkg/nav`, `pkg/layout`, `pkg/code`.

### 1.3 Recommendation

- **Chosen: MyGo native UI (`github.com/egoist/mygo/ui`) with Lobe MyGo (`github.com/lobehub/lobe-mygo`) as the component layer, as directed.** It satisfies the Go-only rule (both pure Go, no cgo, GPU-drawn native UI, no webview) and removes the largest Phase-2 risks identified in `implementation/implementation-roadmap.md`: the code editor comes from MyGo `ui/editor`, the virtualized lists from MyGo `ui`, and the entire control vocabulary from Lobe.
- **Hard rule:** use **only** the native-UI half of MyGo (`mygo.NewWindow(mygo.WindowOptions{Content: ui.View(...)})`). Do **not** use `WindowOptions.URL`, `SetFrontend`, `Protocol`-served web pages, or `WebView`/`ui.WebView` for the application's own interface — those render HTML pages in a system webview and would violate the no-web-frontend constraint. The single legitimate use of a web view is rendering an **HTTP response body** in a response-viewer pane, which is content the user requested, not application UI (and even that should be optional, since a web view may be unavailable on Linux without WebKitGTK).
- **Accept the cost:** MyGo is pre-1.0, so treat minor updates as breaking changes. Pin the version in `go.mod`, isolate every MyGo call inside `internal/ui/`, and never import `github.com/egoist/mygo` outside `internal/ui/*` and `cmd/fearless`.
- **Lobe placement: the same rule applies.** Import `github.com/lobehub/lobe-mygo/pkg/*` only inside `internal/ui/*`. Presenters never see Lobe types; they produce view-models and the widgets render them. `theme.Apply(c)` is called once per root view, and `theme.TokensOf(c)` is the only token source.
- **Contingency: Gio,** if MyGo's API churn or a missing capability becomes blocking. The presenter layer (§3 of `go-architecture.md`) is toolkit-agnostic, so only `internal/ui/widgets` would be rewritten.
- **Fyne:** rejected as primary — CGO toolchain on every CI runner plus a widget set that needs as much custom work as Gio.
- **Wails:** excluded by the Go-only constraint.

### 1.4 Threading rules (framework-specific, keeps the core safe)

| Framework | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MyGo      | `App.Run()` **must be called from `main`** (MyGo locks the main goroutine to the UI thread). Other API calls are safe from any goroutine — they are forwarded to the main thread and wait for the result. A view is a pure function of app state, rebuilt from `ui.View(fn)`, and **all** UI mutations happen in that function; background results reach it via `Window.Update(fn)` or `Context.Invalidate()`. Event listeners run on the main thread and must stay short.                                                    |
| Lobe MyGo | Same rules as MyGo — Lobe components are ordinary `ui.Element` builders, not a separate runtime, so they inherit MyGo's threading model with no additional constraint. One addition: `theme.NewConfig` docs warn that "every Config is remembered", so build the `Config` **once** at startup and reuse it; do not construct one per frame. `field.Upload`'s `Picker` runs "from a goroutine of its own", so the `OnFiles` callback arrives off the UI thread and must marshal through `Window.Update` before touching state. |
| Gio       | UI is driven by the event loop in `main`; **all** widget state updates happen inside the frame function. Core events arrive on a channel and are drained at frame start (`select` with `default`). Never touch UI state from a goroutine.                                                                                                                                                                                                                                                                                     |
| Fyne      | UI state must be updated on the app goroutine; wrap background updates in `fyne.Do` / `DoAndWait` (v2.6+).                                                                                                                                                                                                                                                                                                                                                                                                                    |

In both cases, presenters convert `events.Event` values into view-model snapshots **on the UI thread**, which is why §3 of `implementation/go-architecture.md` keeps state single-owner.

## 4. Versioning and supply-chain policy

1. `go.mod` pins exact versions; no `latest` in automation.
2. MyGo is pre-1.0 (v0.8.3) and documents that minor releases may break API → pin the version in `go.mod`, treat upgrades as migrations, and run golden-screenshot/widget tests (`ui.Tester`) after each bump. Gio and other pre-1.0 modules follow the same rule.
3. **Lobe MyGo has no tagged release** (only a pseudo-version `v0.0.0-…-5e5fea5`). Pin the pseudo-version exactly, vendor it, and treat any update as a migration. Because Lobe sits on top of MyGo, a MyGo bump can break Lobe even when Lobe itself is unchanged — bump them together and run the widget suite.
4. Vendor dependencies (`go mod vendor`) for reproducible offline builds.
5. Every new dependency requires: pure-Go-friendly, active maintenance within 12 months, license compatible with the project, and no network access at init.
6. `govulncheck` in CI.
